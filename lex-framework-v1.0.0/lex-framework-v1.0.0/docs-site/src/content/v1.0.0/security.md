# Authentication, tenancy and safe REST writes

Views require authentication by default; `ViewAccess::Public` is explicit. Lex builds the configured authentication chain from `security.authentication.backends` (`session`, `bearer`, `cookie`). Applications own identity enrollment and credential delivery. Backend errors and invalid supplied credentials fail authentication. All backends are evaluated: a valid session cannot hide an invalid bearer token, and multiple valid mechanisms are rejected as ambiguous. Anonymous fallback occurs only when every mechanism abstains.

`FrameworkAuthService` issues/revokes database sessions and bearer tokens. Raw credentials are delivered once and stored as SHA-256 hashes, not plaintext. Issued credential Debug output is redacted. Lifetimes must be positive and fit signed epoch arithmetic. Do not log returned token/cookie/CSRF values. PasswordField uses Argon2 with OS randomness; enforce application password policy before hashing.

Signed cookies are HMAC-SHA256 authenticated, not encrypted. Subjects and scopes are visible to holders. Keep at least 32 random secret bytes in the configured environment variable; rotate secrets deliberately. Signature verification rejects altered subjects/scopes/expiry. Cookies expire but have no database-backed per-cookie revocation; use sessions when that guarantee is required. Cookie/session unsafe methods require the matching CSRF header by default. Bearer authentication does not require cookie-oriented CSRF. Production settings require secure transport and CSRF for configured cookie/session mechanisms.

A tenant resolver must derive an authorized tenant from verified identity state. Never trust a body `tenant_id`. QuerySets for tenant-aware models require `.for_tenant(...)`; use the authoritative request context. Global scope requires explicit authorization. Permission checks on tenant-owned objects reject missing or mismatched tenant context. The database permission backend checks membership and live grants. Scope-based tenant admin/member markers require tenant context but do not independently prove persisted membership; applications choosing scopes must validate that binding in their resolver.

`SerializerPolicy::for_model` makes primary keys, timestamps, tenant, soft-delete and version fields read-only. Common ownership and privilege names (`owner_id`, admin flags, role and permission fields) also default to read-only. Use `.allow_write_fields(&["title"])` before exposing a model: application-specific sensitive names cannot be inferred reliably. The allowlist rejects unknown or already read-only selections. `set_field` is an explicit advanced override, so review changes to security defaults carefully. Model existence must never imply client write permission. REST write/object checks deny by default. Relations and queries should retain the same tenant scope. Avoid global scope to work around missing tenant initialization.

HTTP errors have `{code, detail, request_id}` and optional `fields`; authentication is 401, forbidden access 403, absence 404, conflicts 409, storage/internal failures 500. Wrapped database errors are redacted. Treat detailed application errors and tracing payloads as sensitive unless explicitly safe.
