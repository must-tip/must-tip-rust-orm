# Deployment behind a trusted proxy

Bind Lex to loopback/private networking. The Axum adapter does not infer TLS from Forwarded or X-Forwarded-Proto; arbitrary client headers never establish a trusted transport. For direct TLS use the configured rustls adapter and test its listener. For termination at Nginx, Caddy or a cloud load balancer, prevent direct public access to the Lex port and configure the proxy to replace incoming forwarding headers.

The generated server requires LEX_TRUSTED_TLS_TERMINATION=true in production before marking requests Secure. This is an operator assertion, not proof of topology. Set it only when **every** reachable route to the server crosses your trusted TLS ingress. Conceptual Nginx deployment: public HTTPS listener proxies to `127.0.0.1:8080`, strips/replaces forwarding headers, limits body size and forwards WebSocket upgrades when used. Conceptual Caddy deployment: an HTTPS site reverse-proxies to the same private listener with explicit upload/timeouts. Cloud load balancers need private security groups/firewall rules and health checks that do not expose protected data. These examples describe the boundary; platform-specific configuration has not been integration-tested here.

Use Secure/HttpOnly/SameSite cookies, narrow credentialed CORS origins, security headers, request limits and real scanner/provider policies. Browser CORS is not authentication. Do not use wildcard origins with credentialed cookies. Deploy a restricted PostgreSQL role; admin migration credentials must not be the request runtime credentials. Force RLS where appropriate and set tenant context transaction-locally. Review migrations on a database copy, back up, apply once, and verify schema/history before rolling out code.

Log request IDs, safe error codes and spans; do not log authentication headers, cookies, passwords, signing secrets, database URLs or bound sensitive values. Authorization uses primary data; do not promise fresh decisions from replicas. Multi-worker throttling/idempotency needs shared state. Test proxy timeouts, upload limits and WebSocket behavior as part of the application's deployment acceptance suite.
