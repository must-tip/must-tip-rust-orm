# Settings, media storage, malware scanning, CORS and browser security

`Config.toml` is the human-editable project configuration generated by `lex create settings`. Secrets do **not** belong in this file.

## Media storage

`[media].storage` supports `memory`, `filesystem`, and `s3`.

- `memory` is intended for tests and is rejected in production.
- `filesystem` is the convenient development default and stores beneath `media.local_root`.
- `s3` is the provider configuration for S3-compatible services. Applications inject a concrete `MediaStorage` implementation using the provider SDK they choose.

### Backblaze B2 S3 API

```toml
[media]
storage = "s3"

[media.s3]
endpoint = "https://s3.us-west-004.backblazeb2.com"
region = "us-west-004"
bucket = "my-private-media"
access_key_env = "LEX_MEDIA_S3_ACCESS_KEY_ID"
secret_key_env = "LEX_MEDIA_S3_SECRET_ACCESS_KEY"
```

Then inject credentials through the deployment secret system rather than committing them:

```bash
export LEX_MEDIA_S3_ACCESS_KEY_ID='...'
export LEX_MEDIA_S3_SECRET_ACCESS_KEY='...'
```

Implement `media::MediaStorage` with the AWS SDK, Backblaze-compatible S3 client, MinIO client, or another S3 library. The rest of the application continues to use the framework storage trait.

## Local and in-memory storage

```rust
use media::{FileSystemStorage, MediaStorage, MemoryStorage};

let local = FileSystemStorage::new("./media").await?;
local.put("avatars/user-1.png", bytes).await?;

let tests = MemoryStorage::default();
tests.put("fixture.txt", b"hello").await?;
```

Object keys reject absolute paths and traversal (`..`). Filesystem writes use a temporary file and rename.

## ClamAV

Run `clamd`, then configure:

```toml
[media]
scanner = "clamav"

[media.clamav]
host = "127.0.0.1"
port = 3310
timeout_secs = 15
fail_closed = true
```

The framework includes `media::ClamAvScanner`, which uses clamd's INSTREAM protocol over TCP. Construct it from the configured host/port/timeout and scan the upload **before** activating the object. With `fail_closed = true`, scanner unavailability must reject/quarantine uploads rather than mark them clean.

## CSP and security headers

The generated settings configure `SecurityHeadersMiddleware`. CSP is expressed similarly to Django-CSP:

```toml
[security.headers]
csp = "default-src 'self'; img-src 'self' https://cdn.example.com; object-src 'none'; frame-ancestors 'none'"
permissions_policy = "camera=(), microphone=(), geolocation=()"
hsts = "max-age=31536000; includeSubDomains"
```

HSTS is emitted only on secure requests. If your trusted edge owns HSTS, configure the application consistently rather than emitting conflicting values.

## CORS

```toml
[security.cors]
enabled = true
allowed_origins = ["https://app.example.com"]
allowed_methods = ["GET", "POST", "PATCH", "DELETE", "OPTIONS"]
allowed_headers = ["Authorization", "Content-Type", "Idempotency-Key"]
allow_credentials = true
max_age_secs = 600
```

Credentialed CORS rejects wildcard (`*`) origins. CORS is not authentication; authorization still runs normally.

## Edge proxies (Azure, Cloudflare, Traefik, etc.)

The framework does not assume that a proxy makes requests trustworthy. TLS can terminate at a trusted edge when `LEX_TRUSTED_TLS_TERMINATION=true` is explicitly set in production. Keep `security.trusted_proxy_hops = 0` until proxy-derived forwarding metadata is intentionally validated by your deployment adapter.
